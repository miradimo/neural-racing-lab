# Neural Racing Lab

- Общаться по-русски; идентификаторы кода — по-английски.
- В начале сессии читать docs/PROGRESS.md, ROADMAP.md, DECISIONS.md,
  LEARNING_NOTES.md и EXPERIMENTS.md.
- Текущий объём работы — PHASE 0. Не переходить к следующей фазе без пользователя.
- Пользователь предпочитает реализацию со стороны ассистента и объяснение теории
  на конкретном коде. Не требовать самостоятельного написания кода как условия обучения.
- Объяснять цель, математический смысл, формы данных и ограничения проверок.
- Использовать Python 3.12, uv, .venv, pyproject.toml и uv.lock.
  Не устанавливать пакеты глобально и не обновлять зависимости без причины.
- Проверки: uv run --locked ruff check ., uv run --locked ruff format --check .,
  uv run --locked pytest. При установленном extra torch добавлять --extra torch,
  чтобы uv сохранял этот набор зависимостей.
- Разделять terminated и truncated; сохранять оба флага в результатах.
  Не называть частичный rollout полным эпизодом.
- Seeds среды и пространства действий задавать явно. Позже отделять training,
  validation и held-out test seeds. Не подбирать параметры по test seeds.
- Не запускать длительные обучения, платные вызовы или внешние побочные действия
  без согласования бюджета. Короткие локальные smoke tests допустимы.
- Не придумывать метрики. Указывать, что реально проверено, а что ещё нет.
- Сохранять структуру, metadata и полезные outputs ноутбуков при точечных правках.
- Не делать commit/push без явной просьбы. Не отменять изменения пользователя.
- Данные, видео, checkpoints и логи хранить вне обычной Git-истории.
- Обновлять документацию и прогресс после выполненных задач.
