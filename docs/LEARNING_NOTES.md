# Первое занятие: среда и цикл взаимодействия

## Цель

Увидеть, какие данные получит будущий PPO и что именно считается эпизодом.
Сейчас работает случайная policy; обучения и нейросети ещё нет.

## Теория

`reset(seed=...)` создаёт начальную ситуацию и возвращает `(observation, info)`.
`step(action)` возвращает `(next_observation, reward, terminated, truncated, info)`.
Среда хранит физическое состояние машины и трассы. Агенту доступно наблюдение:
RGB-кадр `(96, 96, 3)`, значения uint8 от 0 до 255. Это не полное физическое
состояние: один кадр не описывает всю динамику. Позже изучим partial observability
и frame stacking, который помогает оценивать движение по нескольким кадрам.

Действие — скалярное целое из {0, 1, 2, 3, 4}. Для установленной версии:
0 — без воздействия, 1 — вправо, 2 — влево, 3 — газ, 4 — тормоз.
Номера действий и знаки поворотов сверяем с исходником установленной среды.

Reward — оценка одного перехода. Это не вероятность действия, не loss и не
готовая метка правильного управления. Случайный агент не использует reward
для изменения поведения; он только собирает статистику.

В CarRacing каждый шаг стоит −0.1, а первое посещение нового участка дороги
даёт +1000/N, где N — число участков сгенерированной трассы. Повторное посещение
того же участка не даёт бонус. При выезде за границы игрового поля награда
перехода заменяется на −100 и эпизод заканчивается. Поэтому быстрое продвижение
по новым участкам выгоднее стояния на месте или движения по кругу в одном месте.
Это встроенная задача оптимизации; мы не добавляем собственный reward shaping.

## Математика

Равномерная случайная policy: π(a | o) = 1/5 для каждого допустимого действия.
Она не зависит от наблюдения o. Независимая последовательность таких действий
обычно даёт плохое вождение; это ожидаемо и не означает поломку среды.

Episode return: R = Σ r_t, t = 0, ..., T−1.
T — фактическое число шагов до конца эпизода, а не число кадров в файле видео.
Видео дополнительно содержит кадр после reset, поэтому записывается T+1 кадров.

Среднее по n эпизодам: mean(R) = Σ R_i / n.
Выборочное стандартное отклонение: s = sqrt(Σ(R_i−mean(R))² / (n−1)).
При n=1 оно не определено: в JSON записываем null, а не ноль.
Три запуска — smoke baseline, недостаточный для вывода о качестве алгоритма.

## Завершение и bootstrap

`terminated=True` означает конечное состояние по правилам задачи, например
выезд далеко за границы игрового поля. `truncated=True` означает отсечение,
например TimeLimit. В обоих случаях перед новым эпизодом требуется reset.
Оба флага сохраняем отдельно; они могут быть истинными одновременно.

В будущих value targets различие будет принципиальным. Для обычного внешнего
time limit с доступным последним наблюдением:

    target = r_t + γ (1 − terminated_t) V(o_next)

На настоящем terminal state будущее обнуляется, а на внешнем time limit
можно оценить продолжение через V. При этом накопление GAE не должно переходить
в новый эпизод после reset. Эти правила реализуем и протестируем в PHASE 2.

## Архитектура и практика

`envs.make_env` задаёт одинаковые правила для всех запусков.
`reset_seeded` отдельно инициализирует RNG трассы и RNG случайных действий.
`random_agent.run_episode` выполняет цикл до одного из флагов конца и суммирует reward.
CLI отвечает за параметры, запись видео и JSON; он не меняет reward.
`manual_control` заменяет случайное действие вводом с клавиатуры.

Попробовать: посмотреть видео, открыть manual control, сравнить длительность и
return. Затем прочитать `run_episode`: в нём виден весь цикл будущего сбора rollout.
Переписывать код самостоятельно не требуется.

## Проверка и типичные ошибки

- Seed среды не задаёт seed action_space: нужны оба.
- Повторяемость проверяется в одном программном окружении; побитовая идентичность
  между разными ОС, версиями Box2D и GPU не обещается.
- Укороченный TimeLimit меняет измеряемый результат; сравнивать надо одинаковые лимиты.
- FPS с рендерингом/видео/ожиданием дисплея не равно чистой скорости Box2D.
- CUDA ускоряет подходящие операции PyTorch, а Box2D продолжает считать на CPU.
- Реальный интерактивный ввод должен быть проверен человеком; headless-тест его не заменяет.

## Итог и следующий шаг

Материал для обсуждения: наблюдение, действие, reward, эпизод и два вида завершения.
Понимание пользователя ещё не проверено. После просмотра демо разберём вопросы,
затем по согласованию перейдём к MDP и discounted return.
